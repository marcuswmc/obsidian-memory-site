Por que existe

Toda sessão nova começa sem memória.

Sem memória

  • Você explica o projeto, onde parou e o que já foi decidido.
  • O agente relê README, código e histórico para se situar.
  • Na compactação, detalhes e motivos somem no resumo.
  • Ideias já descartadas voltam a ser propostas.

Com Obsidian Memory

  • O contexto do projeto chega pronto no início da sessão.
  • "Onde paramos?" é respondido sem abrir nenhum arquivo.
  • A conversa inteira é arquivada antes de cada compactação.
  • Decisões ficam registradas com o porquê, e o que não fazer também.

Como funciona

Hooks cuidam de cada sessão. Você só trabalha.

  1. SessionStart

    Contexto pronto

    O CLAUDE.md do vault carrega com o projeto, e o hook injeta o resumo da última sessão.

  2. Durante a sessão

    Leitura sob demanda

    Specs, decisões e sessões antigas só entram no contexto quando a tarefa precisa.

  3. PreCompact

    Nada se perde

    Antes de compactar, a conversa é arquivada. Depois, o contexto do projeto volta.

  4. SessionEnd

    Arquivo e commit

    Salva a conversa em daily/ e comita só o vault, se você usa git. Nunca faz push.

O vault é só uma pasta de Markdown

obsidian-vault/ fica ao lado do seu código. O Claude lê e escreve; você pode abrir no Obsidian para navegar pelas notas, ou nunca abrir.

CLAUDE.md
O que é o projeto, stack, estado atual, decisões, mapa de arquivos e o que não fazer.
daily/
Resumo de cada sessão e a conversa arquivada, por dia.
decisions/
Decisões numeradas, com o contexto e o porquê.
obsidian-vault/
├── CLAUDE.md          # contexto do projeto
├── _index.md          # índice gerado
├── 00-inbox.md        # capturas rápidas
├── daily/23-09-2026/
│   ├── session-18h40.md
│   └── transcript-*.md # fora do git
├── specs/  plans/  processes/
├── decisions/         # 0001-*.md …
└── bugs/  retro/

O que você ganha

Continuidade de projeto, não de conversa.

Retomada instantânea

A pergunta "onde paramos?" é respondida com o que já está no contexto, em uma única chamada ao modelo.

Menos tokens

Só o CLAUDE.md e a última sessão entram no início, alguns KB. O resto fica no disco até ser útil.

Arquivo automático

Toda sessão é salva com comandos e respostas, na compactação e no fim.

Decisões que ficam

Registros numerados e uma lista do que não fazer evitam rediscutir o que já foi resolvido.

Git opcional e seguro

Commits locais só do vault. Antes de cada commit, o plugin procura chaves e tokens e bloqueia se achar.

Obsidian opcional

Registra e abre o vault no Obsidian, com notas diárias e templates prontos. Ou use só o Markdown.

Benchmark

Menos tokens para se situar. Mais para trabalhar.

Instalar

Dois comandos dentro do Claude Code.

  1. Adicione o marketplace

    /plugin marketplace add marcuswmc/obsidian-memory-plugin

  2. Instale o plugin

    /plugin install obsidian-memory@obsidian-memory

  3. No seu projeto, crie o vault

    /obsidian-memory:vault init

    O Claude pergunta se você quer versionar o vault com git e usar o Obsidian. As duas coisas são opcionais.

Perguntas

Antes de instalar

Preciso usar o Obsidian?

Não. O vault é uma pasta de Markdown que o Claude lê e escreve. O Obsidian só serve para você navegar pelas notas, se quiser.

Minhas conversas vão para o git?

Não. As conversas arquivadas ficam fora do git. Se você ativar o git, só as notas do vault são comitadas, localmente e sem push.

Funciona em projetos que já existem?

Sim. Rode init na pasta do projeto: o Claude explora o código e preenche o CLAUDE.md com o contexto.

E se eu não rodar o init?

Nada acontece. Os hooks só agem em projetos que têm vault, e o plugin nunca cria um sozinho.

Em que idioma ficam as notas?

No idioma da conversa. As datas usam o formato dd-mm-aaaa.
