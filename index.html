Why it exists

Every new session starts with no memory.

Without memory

  • You explain the project, where you stopped and what was already decided.
  • The agent rereads the README, the code and the history to get its bearings.
  • When the conversation is compacted, details and reasons get lost in the summary.
  • Ideas you already rejected get proposed again.

With Obsidian Memory

  • The project context is ready when the session starts.
  • "Where did we leave off?" is answered without opening a single file.
  • The whole conversation is archived before every compaction.
  • Decisions are recorded with the reasons behind them, and so is what not to do.

How it works

Hooks handle every session. You just work.

  1. SessionStart

    Context ready

    The vault's CLAUDE.md loads with the project, and the hook adds the last session summary.

  2. During the session

    Read on demand

    Specs, decisions and older sessions only enter the context when the task needs them.

  3. PreCompact

    Nothing gets lost

    Before compaction, the conversation is archived. Afterwards, the project context comes back.

  4. SessionEnd

    Archive and commit

    Saves the conversation to daily/ and commits only the vault, if you use git. Never pushes.

The vault is just a folder of Markdown

obsidian-vault/ lives next to your code. Claude reads and writes it; you can browse it in Obsidian, or never open it at all.

CLAUDE.md
What the project is, the stack, current state, decisions, a file map and what not to do.
daily/
A summary of each session and the archived conversation, by day.
decisions/
Numbered decisions, with context and the reason why.
obsidian-vault/
├── CLAUDE.md          # project context
├── _index.md          # generated index
├── 00-inbox.md        # quick captures
├── daily/23-09-2026/
│   ├── session-18h40.md
│   └── transcript-*.md # kept out of git
├── specs/  plans/  processes/
├── decisions/         # 0001-*.md …
└── bugs/  retro/

What you get

Continuity for the project, not just the chat.

Instant resume

"Where did we leave off?" is answered from what's already in context, in a single call to the model.

Fewer tokens

Only CLAUDE.md and the last session load at the start, a few KB. Everything else stays on disk until it's useful.

Automatic archive

Every session is saved with its commands and replies, at compaction and at the end.

Decisions that stick

Numbered decision records and a "do not" list stop settled questions from being reopened.

Optional, safe git

Local commits of the vault only. Before each commit, the plugin scans for keys and tokens and blocks the commit if it finds any.

Optional Obsidian

Registers and opens the vault in Obsidian, with daily notes and templates set up. Or just use the Markdown.

Install

Two commands inside Claude Code.

  1. Add the marketplace

    /plugin marketplace add marcuswmc/obsidian-memory-plugin

  2. Install the plugin

    /plugin install obsidian-memory@obsidian-memory

  3. Create the vault in your project

    /obsidian-memory:vault init

    Claude asks whether you want to version the vault with git and use Obsidian. Both are optional.

Questions

Before you install

Do I need Obsidian?

No. The vault is a folder of Markdown that Claude reads and writes. Obsidian is only for browsing the notes yourself, if you want to.

Do my conversations end up in git?

No. Archived conversations stay out of git. If you turn git on, only the vault notes are committed, locally and never pushed.

Does it work on existing projects?

Yes. Run init in the project folder: Claude explores the code and fills in CLAUDE.md with the context.

What if I never run init?

Nothing happens. The hooks only act on projects that have a vault, and the plugin never creates one on its own.

What language are the notes in?

The language of your conversation. Dates use the dd-mm-yyyy format.

Is this an official Obsidian or Anthropic product?

No. It's an independent open-source project. It works with Claude Code and stores notes in a format Obsidian can open.
